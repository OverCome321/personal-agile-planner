# Иерархическая структура работ

| Код | Этап жизненного цикла | Результат | Ветка |
|---|---|---|---|
| 1 | Анализ | Назначение, ограничения и критерии приемки | analysis/requirements |
| 1.1 | Сбор требований | Сценарии личного спринта и работы с карточкой | analysis/requirements |
| 1.2 | Проверка требований | Правила оценок, дат и резервной копии | analysis/requirements |
| 2 | Проектирование | Модель задачи, компоненты и интерфейс | design/architecture |
| 2.1 | Модель данных | Task и Sprint как фильтр задач | design/architecture |
| 2.2 | Интерфейс | Канбан-доска и редактор карточки | design/architecture |
| 3 | Реализация | Рабочий локальный прототип | feature/kanban |
| 3.1 | Логика | Валидация, прогресс, WIP | feature/kanban |
| 3.2 | Интерфейс | Формы, фильтры, перетаскивание | feature/kanban |
| 3.3 | Хранение | localStorage и резервная копия | feature/backup |
| 4 | Проверка | Тесты и проверка пользовательских сценариев | test/acceptance |
| 5 | Выпуск | README, отчёт, исходный код версии 1.0 | release/v1.0 |
| 6 | Сопровождение | Исправления с отдельными коммитами | maintenance/fixes |

Модель — итеративная: после проверки каждое изменение возвращается к требованиям и проходит новый короткий цикл. Ветка main содержит проверенный результат. ИСР относится к работам; дерево веток Git является способом вести их результаты, а не заменяет саму ИСР.

## Роли и права

В локальном приложении единственный пользователь — владелец своего плана: создаёт, изменяет и удаляет задачи, скачивает и восстанавливает копии. Доступ другим пользователям не предоставляется.

В репозитории владелец управляет ветками и публикацией. Публичный посетитель читает и клонирует код. Роли разработчика (запись в рабочие ветки) и рецензента (обсуждение изменений без административных прав) предусмотрены для дальнейшего расширения команды; реальные дополнительные участники не назначались. Права на удалённом сервере управляются GitHub, а локальные ветки сами по себе не являются средством ограничения доступа.
